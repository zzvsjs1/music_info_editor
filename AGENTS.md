# Working on Metadata Polisher

Use [CONTRIBUTING.md](CONTRIBUTING.md) for environment setup, commands and release checks. The supported development target is conventional, GIL-enabled CPython 3.14 on Windows. Application modules named below are under `src/metadata_polisher/`.

## State and interface

- Keep application rules in Python services and immutable session transforms in `session/`. `ui/quick/backend.py` owns the session and dispatches commands by stable ID. QML presents their results. The historical `--qml` switch launches the same Qt Quick interface.
- Portable settings, layout, logs and optional reports live beside the executable, or in the working directory in source mode. Preserve existing preference keys. Check writability at start-up. Library state, inclusion, Undo, provider cache and credentials last one session.
- Protect pending decisions on rescan, folder replacement and exit. Default to Cancel. Distinguish the typed folder from the loaded library. A failed or cancelled replacement retains the review, and cancelling restores the loaded path. Only a successful replacement starts a fresh review and write selection.
- Keep row highlighting, review scope, metadata decisions, rename decisions and write inclusion independent. Use file and field identities across sorting, selection changes and projection resets. The default Files order is numeric Disc → Track → File. Treat an absent disc as disc 1 for a numbered track, put missing tracks last on their disc and wholly unnumbered files last by name. The file header menu restores this order. Metadata fields keep a fixed order.

## Review, navigation and filenames

- Keep the separate review window closed on start-up. It follows file selection while open. Find Metadata opens it, and closing retains decisions. Present Metadata review → Filename review → Review & Apply. Give the field table spare space, expand filename review for suggestions or blockers and keep the final action reachable below the scroll area. Compact layouts keep Field, Final and Status visible, with original and proposed values still accessible.
- Apply field actions to the highlighted fields in the declared scope (Selected files, Current group, Included files or All library files). Keep existing and Use proposed resolve per file. Skip absent proposals, distinguish Empty from No suggestion, and label unreadable and unsupported values. Accept safe suggestions only fills missing fields from confident, non-conflicting proposals. Track/disc number and total are independently editable. Batch details expose each file’s values and proposal sources.
- Enter on an album moves focus to Files, Enter on a file opens review, and Enter on a field opens copyable values. F2 or double-clicking Final edits. In Files, Ctrl+A highlights and Space toggles inclusion. In review, Alt+Left/Right navigates with selected fields retained, Ctrl+Z undoes even without file highlighting, and Ctrl+Enter opens the summary. Scope shortcuts to the active window and editor. Enter accepts a position, Ctrl+Enter accepts a text edit and Escape cancels.
- Keep F1 help in `ui/quick/settings.py` aligned with the QML windows and shared tables. Support range selection, Page Up/Down, Ctrl+Home/End, Left/Right to reveal columns and Menu or Shift+F10 for column settings. Short windows move secondary commands into overflow menus. Respect the platform style and explicit Qt overrides. Settings uses Fusion tabs, with overflow navigation and Ctrl+Tab/Ctrl+Shift+Tab from inputs.
- Splitting or merging groups resets candidate selection and mapping. Warn and allow cancellation when candidate decisions are affected. Preserve independent manual, Clear, Keep existing and filename choices. Undo across regrouping, language or search-term changes must retain independent edits without restoring obsolete provider evidence or completed writes.
- Use the saved Settings template for every rename workflow. The default is `[%discnumber%.]%tracknumber%. %title%`. Omit an optional group if a referenced field is unavailable. Keep the extension, validate Windows names and collisions, and bound minimum padding to 1–10 digits. Report invalid saved widths and restore safe defaults. Typing `%` opens field suggestions. Enter or Tab replaces just the current token, Escape closes the list and Ctrl+Space reopens it. Field syntax and completion live in `rename/`.
- Filename previews follow scope and decisions while open. The Rename files dialogue stages choices until accepted. Unticking a queued rename keeps the filename. Accepting groups its rename decisions into one Undo action and includes the chosen files alongside earlier inclusions. Cancelling the final summary keeps those prepared choices. Renaming from existing tags works offline across groups.

## Provider and format contracts

- Only explicit lookup or connection testing contacts the selected provider. Support MusicBrainz, VGMdb and None, with no cross-provider fallback. Keep provenance available after a switch. Multi-album lookup runs serially. Candidate windows identify the captured local album even if the main selection moves. Failed repeat searches retain the previous release, mapping and review. Log VGMdb challenges as `ACCESS_DENIED`. Tell the user the request was blocked and offer a retry later or a provider change in Settings.
- Keep parsing in `providers/` and deterministic ranking in `matching/`. Scores rank candidates. Preserve original search text when adding MusicBrainz alias searches and cleaned catalogue/disc-title fallbacks. A manual mapping may use an unused provider track or leave a file unmapped. Use Settings inherits language preferences, while Auto uses existing library text to choose among supplied variants. Track composers require track, work or explicit all-tracks evidence. Partial lists cannot establish totals.
- Use bounded HTTPS requests, rate limits and verified TLS. Honour the explicit direct/manual proxy route independently of environment proxies. Stage and test credentials separately from active session credentials. Saving for the session activates them, and Forget or exit removes access. Keep contact information for the MusicBrainz User-Agent in-session and redact secrets from diagnostics.
- See `formats/` for FLAC Vorbis comments, MP3 and RIFF/WAVE ID3, MP4 audio atoms and TAK APEv2. Preserve unmanaged metadata, representable separate values and supported existing ID3v2.3/v2.4 versions. New ID3 tags use v2.4. Block unsafe v2.3 representations, expose contradictory aliases for review and report WAV INFO/BWF separately. Keep recognised unsupported media visible without write controls. The scanner ignores CUE sheets and EAC logs.

## Apply and recovery

- Freeze the included files and reviewed changes into one immutable summary for both windows. Identify files by library-relative path and show actual before/after values. Only final **Apply changes** starts writing. See `session/apply_preparation.py`, `application/apply.py` and `infrastructure/transaction.py`.
- Recheck filesystem state and validate the change set. Write approved fields to a temporary sibling and reopen it to verify metadata, duration and available stream properties before commit. A rename-only operation skips tag writing. Verify the published destination before removing the original. Retain both copies and report the partial outcome if original cleanup fails. Runtime verification does not hash the audio payload.
- Stop remaining files in a failed album. Honour cancellation before commit and retain completed writes. Reread successful files before showing Written and refresh groups from saved tags. Remove completed and unchanged files from inclusion, keep unfinished files included, preserve unrelated pending reviews, and require a rescan after an uncertain outcome or failed reread.
- Backups and JSON reports are opt-in. Mirror source-relative backup paths beneath an operation directory. Reports record actual outcomes and provenance. Report-writing errors leave completed audio changes in place.

## Verification and distribution

- Use synthetic responses and generated disposable media in the default offline suite. For tag mapping changes, check authoritative format documentation and test raw on-disk representations. The generated WAV integration cases, adapter tests and optional real-container checks cover different behaviours.
- Treat private originals as read-only in automated and manual tests. `tests/localmedia/test_user_media_contract.py` selects at most one sample per supported format from the optional media root (default `musics/`). It writes only to separate pytest temporary copies and checks source digest, size and modification time afterwards. The independent raw FLAC/MP4 checks also take temporary copies of explicitly supplied samples. Missing samples skip their checks.
- For manual Apply checks, copy samples into a dedicated temporary folder outside the library and point the application there. Verify the saved tags and filenames on the copies and confirm the originals still match their recorded digests, sizes and modification times. Remove the test-owned private copies after verification, including renamed outputs and any test backups. Keep originals outside the cleanup scope.
- Live tests require separate opt-in for the selected provider. Report skips and access denials separately from passes.
- For UI changes, use the offscreen runner and the real-scene regression tests in `tests/ui/`. Resolve clicks from delegate geometry. Check native Windows painting, focus, DPI and process lifecycle separately. After QML or packaging changes, exercise scan, review and confirmed Apply with disposable media in the complete frozen folder.
- Keep QML in Python package data and the PyInstaller bundle. `scripts/build_windows.py` stages replacements and preserves local settings, logs and reports on rebuild. Distributable folders exclude this runtime state and retain the complete bundled dependencies. Review source archive and wheel contents with `scripts/check_release.py`. The initial public release is source-only. CI checks packages without publishing. Consult [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) before distributing frozen binaries.
